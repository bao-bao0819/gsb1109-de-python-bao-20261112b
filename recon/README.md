# 库存流水区间对账（recon）

按发生顺序流式读入入库 / 出库 / 实盘流水，逐条维护余额的可行整数区间，
给出相邻两次实盘之间的可成立余额范围；最早出现矛盾的区间会标出导致矛盾
的那一条业务记录，其后的流水不再继续推断。

## CSV 格式

表头大小写不敏感，中英文均可：

| 列 | 可写表头 | 含义 |
| --- | --- | --- |
| 类型 | `type` / `类型` | `IN`（入库）、`OUT`（出库）、`COUNT`（实盘/盘点） |
| 下界 | `lo` / `下界` | 数量下界（看得清时与上界相同） |
| 上界 | `hi` / `上界` | 数量上界 |
| 备注 | `ref` / `备注` | 单号等，可留空 |

也可以用单列 `qty` / `数量` 代替 `lo`、`hi`，表示数量确定。示例见
`sample_ledger.csv`。

## 用法

```bash
python -m recon sample_ledger.csv
```

退出码：`0` 全部区间可对平；`1` 出现不可能对平的区间；`2` CSV 本身格式错误。

## 为什么只对两端加总不够

余额任何时刻都不能为负。一笔出库的下界若超过当时的可达余额上界，即使整段
净变动能对上末端实盘，该区间仍然不可能成立。引擎对每一步维护闭区间
`[bal_lo, bal_hi]`：

- 入库 `x ∈ [lo, hi]`：新区间为 `[bal_lo + lo, bal_hi + hi]`
- 出库 `x ∈ [lo, hi]`：新区间为
  `[max(0, bal_lo - hi), bal_hi - lo]`；若上界为负则区间为空，立即判死
- 实盘：把当前区间与实盘窗口取交集；不相交则该区间不可能对平

读取是单遍流式的，任何时刻只保留当前区间内的步骤，不缓存整份账册。

## 可对平但不唯一时

不直接指定某笔为错账。引擎先用反向 pass 从末端实盘倒推每一步余额的可行
窗口（同时纳入非负约束与起点实盘窗口），再前向分别逐点取最小、最大余额，
构造两条完整、合法且互不相同的中间走势；每个取值都严格落在该记录自己的
`[lo, hi]` 内。若两条极值走势重合，说明约束实际上把每笔数量都钉死了，
报告按唯一走势处理。
